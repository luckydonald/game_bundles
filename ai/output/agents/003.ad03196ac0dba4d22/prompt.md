## What you learned already (don't re-derive)
- `https://www.greenmangaming.com/bundles/` is server-rendered HTML (not an SPA fetch) with a `<div class="product-grid">` containing one `<div class="product-card" data-category="...">` per bundle. Relevant categories seen: `video-games`, `books-comics`, `software` — only `video-games` should become game lists (mirror Humble's "Books and Software are ignored" precedent).
- Each `product-card` has: `data-end-date="2026-07-21T18:00"` attribute (no timezone marked — treat as needing investigation: check response `Date` header or assume UTC/site timezone, be conservative and document uncertainty rather than silently guessing wrong; DIG had a similar "no structured dates" problem and solved it by deriving relative to crawl time — consider whether end-date here is reliable enough to use directly, it looks more structured than DIG's countdown string so probably fine, but verify format is always `YYYY-MM-DDTHH:MM` with no offset), a `<h3 class="product-title">`, and an `<a class="cta-button" href="...">` linking to the actual bundle detail page, e.g. `https://www.greenmangamingbundles.com/bundles/metroidvania-madness/?utm_term=flatpage` — note the *different domain* (`greenmangamingbundles.com` vs `greenmangaming.com`). The slug (`metroidvania-madness`) is the stable bundle identifier — use it as the list/archive directory key, analogous to DIG's bundle number or Humble's machine_name.
- The bundle detail page (`greenmangamingbundles.com/bundles/<slug>/`) is also server-rendered (Django + htmx, not Angular). It shows the *highest* tier's cumulative item list by default (e.g. "The Gold bundle includes" heading followed by ALL items across all tiers, in ascending-tier order in the DOM — first N items belong to the cheapest tier, next M to the next tier, etc). Tier metadata (name, price, cumulative item count) is separately available from the tier-selector radio buttons near the bottom of the page: `<input type="radio" name="amount" data-upgrade-tier-id="bronze" value="bronze:8.00" .../>` next to `<small>2 Items</small>` and `<span class="price">€8.00</span>`, one such block per tier (bronze/silver/gold seen; there may be a "custom amount" option too — ignore that one, it's a pay-what-you-want slider, not a fixed tier). Cross-check: cumulative item counts per tier (2, 4, 6) exactly matched the DOM order of `<strong class="game-title">` entries in groups of 2 — verify this ordering assumption holds by fetching `/bundles/<slug>/switch_tier/` with the appropriate `hx-vals`/form params for a lower tier (see the `hx-get="/bundles/<slug>/switch_tier/"` wrapper div and its `hx-include` list: `input[name='amount']:checked,input[name='custom_amount'],input[name='currency_code']`) if you want to confirm precisely which items belong to which tier rather than relying on DOM-order inference. This precision matters for building correct cumulative tier lists (mirror `HumbleTier`/`HumbleArchive`'s cumulative-tiers model in `src/game_collections/sources/humblebundle/models.py`).
- Each item is a `<figure class="bundle-item" hx-get="/bundles/<slug>/product/<id>/" ...>` with `<strong class="game-title">Name</strong>` — the numeric id in that URL (e.g. `346`) is GMG's own internal product id, NOT a Steam AppID. Fetching that URL directly with header `HX-Request: true` returns an HTML fragment (confirmed working via plain `curl`, no Cloudflare/JS challenge) containing a `<dl>` of `<dt>DRM</dt><dd>Steam</dd>`, `<dt>Platform</dt><dd>Windows</dd>`, `<dt>Developer</dt><dd>...</dd>`, `<dt>Publisher</dt><dd>...</dd>`, plus a description paragraph and system requirements. **There is no direct storefront link/ID anywhere** — unlike DailyIndieGame, GMG bundles need title-based storefront resolution like Humble does. The DRM field tells you which storefront(s) to search (seen: "Steam"; there may be others like "GOG", "Uplay"/Ubisoft, "Standalone" — treat unknown DRM values leniently: map recognized ones to the existing `StoreName` values (`steam`/`gog`/`epic`/`ubisoft`), and fall back to leaving the item unresolved (or skip resolution and just record it as unresolved with no store guess) for anything else you can't confidently map — don't invent new store types).
- No pagination was found on the bundles index (only 4 cards existed at fetch time) — assume it's a small live list like DailyIndieGame's weekly bundles, not humble's paginated discovery either.
