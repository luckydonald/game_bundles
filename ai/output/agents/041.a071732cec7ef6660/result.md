## Report

### 1. `src/game_collections/cli.py` — structure & conventions

- **App setup**: `app = typer.Typer(no_args_is_help=True, pretty_exceptions_enable=False)` at cli.py:104, plus a nested `scrape_app = typer.Typer(no_args_is_help=True)` at cli.py:105 (mounted as a subcommand group — look at how `scrape_app` gets added to `app`, e.g. `app.add_typer(scrape_app, name="scrape")`, to mirror for a top-level `install`/`uninstall`).
- **Command definition style**: flat `@app.command("name")` decorated functions (e.g. `validate_command` cli.py:140-141, `list_command` cli.py:155-156, `schema_command` cli.py:216-217). Options are declared via `Annotated[Type, typer.Option("--flag", help="...")] = default` and arguments via `Annotated[Type, typer.Argument(help="...")]` — no `click.Context`/callback style, everything is plain function params.
- **Output**: exclusively `typer.echo(...)` (stdout) and `typer.echo(..., err=True)` (stderr) — no `print()`, no `rich.console.Console` for user-facing output anywhere in cli.py (rich is only used inside `apply/tree_checkbox.py` and `apply/tui.py` for the Textual picker's styling, not as a general console helper). Follow the same `typer.echo` convention for `install`/`uninstall` messages.
- **Error handling**: consistently `except (OSError, ValueError, SomeDomainError) as error: typer.echo(str(error), err=True); raise typer.Exit(1) from error`. Domain-specific exceptions are plain `RuntimeError` subclasses (e.g. `GitAutocommitError`, `SteamApiError`, `SteamDbCrawlError`) raised from lower-level modules and caught in cli.py. Manual validation errors use `typer.echo(msg, err=True); raise typer.Exit(2)` (e.g. cli.py:553-554 for an invalid `--git-style` value).
- **Subprocess/git usage**: `scrape humblebundle` and `scrape isthereanydeal` are the only commands that shell out, via the `game_collections.git_ops` module (imported at cli.py:27, used at cli.py:557-558, 632, 636, 824-825, 887-892). They compute `repository_root = Path.cwd().resolve()` (cli.py:179, 556, 659, 722, 823) — notably **not** `git rev-parse --show-toplevel`; the existing code assumes the CLI is invoked from the repo root rather than detecting the toplevel dynamically. If `install`/`uninstall` need true git-root detection, that'd be a new pattern, not a reused one.
- **Interactive prompts**: `typer.confirm` isn't used directly in cli.py's visible portion but `_confirm_unverified_ownership` (cli.py:1121) exists as a precedent for a confirm-gated flow — worth reading in full for the confirm-then-continue pattern to mirror for `uninstall`'s "also run `uv tool uninstall`?" prompt.

### 3. `tests/test_cli.py`

- Uses **Typer's `CliRunner`** (`from typer.testing import CliRunner`, test_cli.py:8) — invoked as `CliRunner().invoke(app, [...])`, with `input="y\n"` for interactive confirms (test_cli.py:124-145) and asserting on `result.exit_code` / `result.output`.
- Uses `pytest`'s `tmp_path` fixture heavily for isolated filesystem roots (e.g. `steam_root = build_fake_steam(tmp_path)`, `lists_root = tmp_path / "lists"`), and `monkeypatch: MonkeyPatch` for env vars (e.g. `monkeypatch.setenv("GITHUB_RUN_ID", "12345")` test_cli.py:350) and presumably `monkeypatch.chdir`/`setattr` elsewhere in the file (worth grepping further for `monkeypatch.setattr` if you need to stub subprocess calls, but no existing example of mocking `subprocess.run` appears in the excerpt read).
- Sibling file `tests/test_git_ops.py` shows the pattern for testing real subprocess/git behavior safely: it builds a **real throwaway git repo under `tmp_path`** (`_init_repo`, test_git_ops.py:18-27) rather than mocking `subprocess`, then runs the actual module functions against it. For `install`/`uninstall`, the equivalent approach would be: don't touch the real `~/.bashrc`/`~/.zshrc` — instead monkeypatch `Path.home()` (or better, have the rc-file/completion-path resolution functions accept an injectable home/config directory) so tests point at a `tmp_path`-based fake home. For `uv tool install` itself, since you don't want to actually install/uninstall packages in tests, that call should be routed through a thin subprocess wrapper that can be monkeypatched (`monkeypatch.setattr(cli, "_run_uv_tool_install", fake)` style) or tested only for the command-construction logic, not the actual execution — there's no existing "dry subprocess" helper to reuse, so this would be new.

### 4. Existing subprocess helper / config-dir pattern

- **Subprocess helper**: `src/game_collections/git_ops.py` has a private `_run(repository_root, *args)` wrapper around `subprocess.run(["git", *args], cwd=..., check=True, text=True, capture_output=True)` (git_ops.py:22-29), but it's git-specific and module-private (not exported/reused elsewhere). There is **no generic subprocess-running utility** in `src/game_collections/` for arbitrary commands like `uv tool install` — you'd write a new one, possibly following the same `check=True, text=True, capture_output=True` style for consistency, and likely put it in a new module (e.g. `install.py`) or a small `subprocess_utils.py`.
- **Config/data directory pattern**: there is **no `platformdirs` usage and no `~/.config/game-collections` pattern anywhere** in `src/game_collections/` — no `Path.home()`, `.config/`, or `XDG` references at all in the source tree. Everything (schemas, selection config, dynamicstore dump, lists, archives) is currently relative to the invoking directory, defaulting to repo-relative paths like `Path("config/apply-selection.yml")`, `Path("lists")`, `Path("archives")` (see the many `typer.Option(...)  = Path("config/...")` defaults in cli.py, e.g. cli.py:409-410, 793-796). This means the "stable path" for the generated completion script and any state you write for `install`/`uninstall` (to make `uninstall` able to find/remove it later) will be a genuinely new pattern in this codebase — you'll need to decide between `platformdirs` (not currently a dependency), a hardcoded `~/.config/game-collections/`, or a `~/.local/share/...`-style location, and add whichever dependency that implies.

### 5. Existing `--git` flag handling (`scrape humblebundle` / `scrape isthereanydeal`)

- Both commands declare `--git` (a bare flag) and `--git-style manual|auto` options (e.g. cli.py:539, 546-547 for humblebundle; cli.py:806, 813-814 for isthereanydeal), validated with `typer.echo(err=True) + raise typer.Exit(2)` if `git_style` isn't `"auto"`/`"manual"` (cli.py:553-554, 820-821).
- Orchestration pattern per command: compute `repository_root = Path.cwd().resolve()` → `pre_crawl_head = git_ops.head(repository_root) if git else None` → `stashed = git_ops.autostash(repository_root) if git else False` (cli.py:556-558, 823-825) → run the actual scrape logic inside a `try`/`except` → on success, if `git`, build a commit message via `_git_commit_message(...)` (cli.py:501-512, invoked at cli.py:629, 887) and call `git_ops.commit_changed_paths(repository_root, [<paths>], message)` (cli.py:632-635, 890) → in a `finally`-like block, `if stashed: git_ops.restore_autostash(repository_root, pre_crawl_head)` (cli.py:636, 892).
- `git_ops.py` (full content read) provides: `head()`, `autostash()`, `commit_changed_paths()`, `restore_autostash()`, all built on the private `_run()` wrapper, plus a custom `GitAutocommitError(RuntimeError)` for unrecoverable stash-restore failures (git_ops.py:12-15). This module is a good template for *style* (small focused functions each wrapping one git subcommand, `check=True` + explicit error class) but it does **not** contain a `rev-parse --show-toplevel` call (only `rev-parse HEAD`) — you'd add that as a new function, e.g. `git_ops.repository_root()` or similar, following the same `_run(...)` pattern, likely with a fallback for "not inside a git repo" (since `install` should presumably also work from an installed/non-repo context when just doing `uv tool install <name>` from PyPI, so the git-root detection is only needed for the editable-install branch).
